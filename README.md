# LLM practice

记录我学习模型调用、关键词检索、语义检索和资料问答的过程。前面的风机、水泵资料是模拟数据，后面换成了施耐德 Easy UPS 公开中文手册。

手册问答已整理成 [独立展示仓库](https://github.com/LiankunYang/industrial-manual-rag)。这里保留按天的练习记录和原实验结果。

## 2026-10-11

### API 调用与关键词检索

先用 Python 调通 DeepSeek，再把四段设备说明放进列表，按关键词找出段落，将原文和来源交给模型。

| 问题 | 关键词 | 当次回答 |
|---|---|---|
| 多久检查风机滤网？ | 滤网 | 每30天检查风机滤网，来源为风机说明第1段。 |
| 风机的生产厂家是谁？ | 风机 | 原文未提供。 |
| 电机的额定功率是多少？ | 电机 | 未检索到相关资料。 |

厂家问题找到了资料，但里面没有答案；电机问题没有找到资料，程序直接返回提示。

换成“过滤网”后，检索得到空列表。原文写的是“滤网”，完整关键词匹配无法识别这两种说法。

### 语义检索

接着用 BGE 中文模型编码问题和原文，按余弦相似度取前两段。四段原文的向量形状为 `(4, 512)`，问题编码时加上模型的检索提示。

“过滤网多久维护一次？”的检索结果：

| 原文 | 相似度 |
|---|---:|
| 每30天检查风机滤网。 | 0.6078 |
| 每90天检查水泵密封。 | 0.4474 |

换成“机器太热应该怎么处理？”也能找到风机过热的段落。不过，问厂家时仍会返回没有厂家信息的段落：取前两条只是排序，不能说明资料里一定有答案。当前没有设置相似度过滤阈值。

这一阶段只查看段落和分数，`get_records()` 根据检索索引取回原文与来源。

## 2026-10-12

### 接通语义检索与回答

把 `semantic_find()`、`build_context()` 和模型调用接起来，只输入问题就能检索并回答。空问题返回“请输入问题”，空资料返回“未检索到相关资料”，都不会请求模型。

滤网和水泵密封问题分别回答30天、90天；厂家问题回答“原文未提供”。过热问题有一次也返回了“原文未提供”，尽管资料里有“先停机，再检查风道”。保存的输出末尾还有一条正确的过热回答，但未标记对应哪次调用，因此先保留这个异常，原因待核对。

这一步使用四段模拟资料，每次提问都会重新编码原文。

### 从 TXT 读取资料

把资料移到两份模拟 TXT，用 `load_records()` 按非空行读取，保留原文件行号。这次读到6条记录，风机过热在第3行，水泵首次运行在第4行。

文件中的过热问题回答了“先停机，再检查风道”。这次资料和问题都带有“风机A”，与前一次条件不同，还不能确定此前异常的原因。

随后把滤网周期从30改为45并保存。重新读取后，回答变成45天，来源仍是第1行。旧的 `records` 不会随文件修改自动更新，需要重新调用 `load_records()`。

### 固定测试与结果记录

固定六个问题，保存检索原文、参考文字和回答。`expected` 留作事后核对，不发送给模型。

| 编号 | 检查内容 | 当次结果 |
|---|---|---|
| T01 | 滤网周期 | 45天，来源为风机说明第1行。 |
| T02 | 换成“过滤网维护” | 45天，引用第1行。 |
| T03 | 过热处理 | 先停机，再检查风道，来源为第3行。 |
| T04 | 水泵密封周期 | 90天，引用水泵说明第1行。 |
| T05 | 错误地假设30天 | 纠正为45天，引用第1行。 |
| T06 | 厂家信息 | 原文未提供。 |

T05、T06另外写了人工评价，前四条没有单独填写 `review`。六条完整记录保留在 [demo.ipynb](demo.ipynb) 的输出中，后面可以用来对比检索或提示词的改动。

### 公开 UPS 手册问答

基于练习程序，把流程用于 [施耐德 Easy UPS 中文手册](https://www.se.com/tw/zh/download/document/SPD_AHUG-AS9C3R_CH/)。选择7页，得到26个短块，保留PDF页码和块编号。原文编码一次，后面的提问复用向量。

运行了15个固定问题，并对一个PowerChute问题比较取1块和3块。主要观察到：

- 默认电压回答为230 VAC，模型纠正了110V的错误前提；R01、R05保存了人工评价。
- 声音报警、绿色模式和事件日志数量三题漏答。候选命中了相关页，但没包含具体依据：前两题需要第15页块01，日志题需要第16页块01。
- 密码和当前电量两题回答资料未提供。
- PowerChute两组回答和引用都符合依据，参考文字从250字增加到872字，这道题的回答没有改善。

运行过程见 [手册问答 Notebook](public_manual/demo.ipynb)，结果见 [15题记录](public_manual/results/llm07_all15.json) 和 [取块数量对比](public_manual/results/llm07_topk_comparison.json)。

## 2026-10-13

### 混合检索与失败修复

沿用练习中的混合检索程序，在语义检索之外增加字符TF-IDF。使用2–4个字符片段，匹配时去掉空白，避免“高效”和“率”被PDF换行拆开后影响查找。两路各取最多8个候选，通过RRF融合排名，最后仍取3块。

这轮保持模型、提示词和最终取块数量一致，只调整检索方法。预期答案和页码用于事后核对。

| 问题 | 新增的依据块 | 新回答 |
|---|---|---|
| R03：声音报警默认设置 | 第15页块01 | 启用。 |
| R04：绿色/高效率模式默认设置 | 第15页块01 | 禁用。 |
| R09：事件日志数量 | 第16页块01 | 最后10个事件。 |

三题的引用和回答通过人工核对。其余12题也保存了回答，但没有逐条新增 `review`。R15问设备此刻的电量，手册只能说明如何显示电量，回答“资料未提供”合理。

对照基线是本轮重新保存的语义检索记录，措辞与前一天略有不同。两轮分别保留在 [对照基线](public_manual/results/llm08_baseline15.json) 和 [混合检索结果](public_manual/results/llm08_all15.json)，前一天的记录也保留。

代码在 [retrieval_upgrade.py](public_manual/retrieval_upgrade.py)，运行过程见 [混合检索 Notebook](public_manual/hybrid.ipynb)。

## 运行与查看结果

```bash
python -m pip install -r requirements.txt
python main.py --preview
python main.py --semantic
python main.py --rag
python main.py
```

- `--preview`：只打印关键词检索结果。
- `--semantic`：用CPU做BGE检索，无需DeepSeek密钥。首次从ModelScope下载模型到 `bge_small_local/`。
- `--rag`：四个示例问题分别请求DeepSeek。
- 不加参数：三组关键词问答，前两组请求模型，最后一组因无资料直接返回。

DeepSeek调用会按平台计费。密钥通过隐藏输入读取，也可以设置环境变量 `DEEPSEEK_API_KEY`。模型文件和密钥不上传。

[demo.ipynb](demo.ipynb) 的“从 TXT 读取资料”部分创建两份模拟TXT，已有文件会保留。也可以传入自己的UTF-8文件，按非空行读取：

```bash
python main.py --semantic --files "practice_documents05/风机说明.txt" "practice_documents05/水泵说明.txt"
python main.py --rag --files "practice_documents05/风机说明.txt" "practice_documents05/水泵说明.txt"
```

公开手册资料准备和单个问答：

```bash
python public_manual/manual_project.py --prepare-only
python public_manual/manual_project.py --question "事件日志最多记录多少个事件？" --top-k 3
```

第一条命令下载并校验官方PDF、提取文字，不调用DeepSeek；第二条使用语义检索，请求一次回答。手册原文版权归厂商，PDF和生成的文字块留在本地。

在VS Code打开Notebook，选择安装好依赖的Python内核。手册基线全流程请求17次，混合检索15次，新五题5次，查询诊断1次。重跑会请求模型并保存结果，原评价需要重新核对。此学习仓库中部分结果使用固定文件名，会覆盖同名本地结果；重跑前可先备份。

只查看结果时，直接在GitHub打开Notebook即可。主 `demo.ipynb` 的公开手册、混合检索、新问题和查询诊断部分读取已保存的JSON，不请求模型。

`status=ok`表示接口完成，页码命中表示候选来自预期页；回答仍要对照具体原文核对。Notebook保存了旧输出，部分文件路径来自原本地环境，重新运行后会显示当前路径。

参考：[DeepSeek接口](https://api-docs.deepseek.com/api/create-chat-completion/)、[BGE模型说明](https://huggingface.co/BAAI/bge-small-zh-v1.5)、[Sentence Transformers检索接口](https://sbert.net/docs/package_reference/util/retrieval.html)。
