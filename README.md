# LLM practice

记录我学习大模型调用、关键词检索和语义检索的小练习。

## 2026-10-11

### API 调用与关键词检索

我先用 Python 调通 DeepSeek，修改问题和回答要求，取出返回的回答。然后把几段设备说明放进列表，按关键词找出相关段落，把原文和来源一起交给模型。

现在的流程是：**输入问题和关键词 → 找资料 → 拼接原文与来源 → 生成回答**。关键词由我手动提供。代码里的四段设备资料是模拟数据，来源名称也是示例。

这次练习的实际输出：

| 问题 | 关键词 | 回答 |
|---|---|---|
| 多久检查风机滤网？ | 滤网 | 每30天检查风机滤网。（来源：风机说明.txt，第1段） |
| 风机的生产厂家是谁？ | 风机 | 原文未提供。 |
| 电机的额定功率是多少？ | 电机 | 未检索到相关资料 |

后两种情况有区别：厂家问题找到了风机资料，但资料中没有答案；电机问题连资料都没找到，会直接返回，不请求模型。这组输出来自我保存的练习 Notebook，重新请求时措辞可能不同。

我还试了用“过滤网”检索，结果是空列表。资料写的是“滤网”，当前匹配要求原文包含完整关键词，所以这里是检索没找到，模型根本拿不到那段资料。

### 语义检索

为了解决换个说法就搜不到的问题，我接着用 BGE 中文模型把问题和原文编码成向量，再按余弦相似度取前两段。四段原文编码后的形状是 `(4, 512)`，问题编码时加上模型的检索提示，原文保持不变。

“过滤网多久维护一次？”这次检索到了：

| 排名 | 原文 | 相似度 |
|---|---|---:|
| 1 | 每30天检查风机滤网。 | 0.6078 |
| 2 | 每90天检查水泵密封。 | 0.4474 |

我也换了几个问题，查看第一条结果：

| 问题 | 第一条原文 |
|---|---|
| 机器太热应该怎么处理？ | 风机过热时，应先停机，再检查风道。 |
| 水泵密封多久检查一次？ | 每90天检查水泵密封。 |
| 设备的生产厂家是谁？ | 水泵出现异常噪声时，应先停机检查。 |

厂家问题仍然返回了段落，但这些资料里没有厂家信息。我的理解是：检索根据语义相似度排序，返回结果并不保证其中有答案，分数也不是回答正确的概率。当前取前两条，没有设置过滤阈值。

这一步先输出检索段落和分数。`get_records()` 用返回的索引取回原文，保留排序和来源。

## 2026-10-12

### 接通语义检索与模型回答

我把找资料、拼接参考文字和请求 DeepSeek 接到一个函数里，现在只输入问题就能完成这几步，不用再手动填关键词。

流程是：**问题 → 语义检索 → 匹配记录 → 带来源的参考文字 → 模型回答**。

`semantic_find()` 返回包含字典的列表，`build_context()` 将它整理成字符串，`answer_with_search()` 返回回答字符串。空问题返回“请输入问题”，空资料返回“未检索到相关资料”，这两种情况提前结束，不请求模型。

保存的练习里得到这些结果，重新请求时措辞可能不同：

| 问题或情况 | 实际输出 |
|---|---|
| 过滤网多久维护一次？ | 每30天检查一次，回答标明风机说明第1段，但没有逐字引用原句。 |
| 机器太热应该怎么处理？ | 原文未提供。 |
| 水泵密封多久检查一次？ | 每90天，引用水泵说明第1段的原句。 |
| 设备的生产厂家是谁？ | 原文未提供。 |
| 空资料 | 未检索到相关资料 |
| 空问题 | 请输入问题 |

过热问题的那次回答不符合预期：资料里有“风机过热时，应先停机，再检查风道。”，还需要核对当次检索结果和传给模型的参考文字。保存的输出末尾另有一条正确的过热回答，但没有标记对应哪次调用，先保留这次异常记录。

这次接通了流程，也看到检索和回答要分别检查：有候选段落不一定有答案，提示词要求引用也不保证模型照做。这一步先用四段模拟资料，每个问题都会重新编码原文。

### 从 TXT 读取资料

我把资料移到两份模拟设备说明里，用 `load_records()` 读成记录列表，再接回原来的问答函数。现在不用把每句话写在代码里。

读取时用 UTF-8，`splitlines()` 按行拆分，`strip()` 清理两端空白。空行不存成记录，但仍计入原文件行号。这次读到 6 条记录：风机过热是第3行，水泵首次运行是第4行；输入空文件列表返回 `[]`。

| 问题 | 保存的实际回答 |
|---|---|
| 风机A滤网多久检查一次？ | 每30天，来源是风机说明第1行。 |
| 风机A过热时应该怎么处理？ | 先停机，再检查风道，引用风机说明第3行。 |
| 风机A的生产厂家是谁？ | 原文未提供。 |

这次过热问题回答符合原文，但资料和问题都带上了“风机A”，不能据此判断之前那次异常的原因。

我已把 TXT 第一行的30改成45并保存。原读取练习最后保留的是修改前的30天回答，后面的固定测试已经验证新原文和回答都是45天，来源仍是第1行。文件改变后，旧的 `records` 不会自动更新，需要重新调用 `load_records()` 才能拿到新内容。

### 固定测试与结果记录

我固定了六个问题，提前写好预期，再保存每次找到的原文、发给模型的参考文字和实际回答。`expected` 只用于检查，不发送给模型。

| 编号 | 检查内容 | 本次实际结果 |
|---|---|---|
| T01 | 滤网周期 | 45天，标明风机说明第1行。 |
| T02 | 用“过滤网维护”换一种说法 | 45天，引用滤网原文和第1行。 |
| T03 | 过热处理 | 先停机，再检查风道，标明第3行。 |
| T04 | 水泵密封周期 | 90天，引用水泵说明第1行。 |
| T05 | 问题错误地假设30天 | 纠正为45天，引用第1行。 |
| T06 | 资料没有厂家信息 | 原文未提供。 |

我重点检查了 T05 和 T06，分别记录“纠正为45天，引用与第1行一致”和“原文未提供，没有编造厂家信息”的判断。完整结果已保存成 JSON，也保留在 Notebook 的输出里。

这只是两份模拟文档、六个固定问题的一次运行，前四条没有单独填写 `review`，目前也没有自动评分。以后改检索或提示词，可以用同一组问题对照原文、回答和来源，保留失败结果再排查。

### 公开 UPS 手册问答

我基于练习程序，把之前的流程用到[施耐德 Easy UPS 中文手册](https://www.se.com/tw/zh/download/document/SPD_AHUG-AS9C3R_CH/)，完成了15个固定问题，以及同一问题取1块、3块的对比。程序提取7页，得到26个短块，每块保留PDF页码和编号；原文只编码一次，后面的提问复用向量。

我主要做了运行、核对回答和引用、查看失败原因。Notebook里审查了默认电压和110V错误前提两题，判断说明也同步进最终结果。预期只用于核对，没有发给模型。

| 观察 | 本次结果 |
|---|---|
| 默认电压与可选电压 | 能区分230 VAC默认值与220/230/240 VAC可选值，也纠正了110V的错误前提。 |
| 声音报警、绿色模式 | 回答“资料未提供”，但第15页表格分别写了启用、禁用；候选漏掉了含设置表的块01。 |
| 事件日志数量 | 回答“资料未提供”；第16页块01含10个事件，检索返回的块02没有这个数值。 |
| 密码、当前电量 | 承认资料缺失，没有用静态手册猜密码或实时数值。 |
| PowerChute取1块与3块 | 两组回答和引用都符合依据，参考文字从250字变为872字，这个样例没有看到回答改善。 |

15次请求都完成了，但`status=ok`只表示接口完成，页码命中也不代表具体依据已找到。我保留了报警、绿色模式、日志数量三处失败，后续再用同一组问题检查改动效果。目前是部分页面、固定问题的一次实验，还没有自动评分。

## 运行

```bash
python -m pip install -r requirements.txt
python main.py --preview
python main.py --semantic
python main.py --rag
python main.py
```

`--preview` 只打印检索结果。直接运行会隐藏输入 DeepSeek API key，也可以通过环境变量 `DEEPSEEK_API_KEY` 设置；三组问题中前两组会请求模型并按平台计费。

`--semantic` 使用 CPU 做本地检索，不需要 DeepSeek 密钥。首次运行会从 ModelScope 下载 `bge-small-zh-v1.5` 到 `bge_small_local/`；模型文件不上传仓库。

`--rag` 接通语义检索和回答，四个示例问题都会请求 DeepSeek，按平台计费。可以先用 `--semantic` 查看候选原文，再检查模型回答是否符合原文。

Notebook 最后一节会创建两份模拟 TXT，已有文件会保留，生成的练习目录不上传。也可以把自己的 UTF-8 TXT 路径传给程序；本节按非空行切分，长文档的切分以后再调整：

```bash
python main.py --semantic --files "practice_documents05/风机说明.txt" "practice_documents05/水泵说明.txt"
python main.py --rag --files "practice_documents05/风机说明.txt" "practice_documents05/水泵说明.txt"
```

在 VS Code 中也可以打开 [demo.ipynb](demo.ipynb)，选择安装过依赖的 Python 内核，逐格运行。Notebook 的调用单元需要联网；这里只用提示词要求模型依据资料回答，引用是否正确仍需要对照原文检查。

参考：[DeepSeek 接口](https://api-docs.deepseek.com/api/create-chat-completion/)、[BGE 模型说明](https://huggingface.co/BAAI/bge-small-zh-v1.5)、[Sentence Transformers 检索接口](https://sbert.net/docs/package_reference/util/retrieval.html)。
